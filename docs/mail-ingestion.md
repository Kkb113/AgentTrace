# Reliable read-only email ingestion

AgentTrace now collects authorized synthetic Outlook messages and Exchange audit
observations. This layer establishes what was observed, which version was read,
and where evidence is missing. It does not decide that an agent sent a message or
that its wording was generated by AI. Those remain two independent downstream
findings. Text style, Sent Items notifications, and successful API calls cannot
establish AI-agent execution.

## Data path and operational boundary

The live path is Graph basic notifications → an East US Event Grid partner topic
with a system-assigned identity → a dedicated Standard LRS queue → the local
collector → a PostgreSQL durable inbox. Only the existing pilot mailbox and the
operator-prepared **AgentTrace Synthetic** folder are enrolled. Folder enrollment
is explicit; new children require enrollment. Fixtures additionally exercise
multiple enrolled folders, replies, forwards, moves, and separate delivery copies.
Shared-mailbox access is supported only when separately enrolled and positively
authorized. This deployment has no enrolled shared mailbox, and archive-mailbox
transitions are outside the stable immutable-ID boundary.

The Graph subscription requests immutable IDs and excludes rich resource data.
Native notifications contain sensitive identifiers and the validation secret but
no message body. The collector validates the subscription, tenant, application,
client state and mailbox resource, then encrypts the locator. Azure Queue receipts
are deleted only after the inbox transaction commits. The alternate local HTTP
receiver answers Graph's validation challenge separately; accepted notifications
receive HTTP 202 only after commit, and storage failure returns 503.

The separate queue account uses the owner-accepted trusted-services network
exception and dedicated-account delivery roles documented in
[the transport review](notification-transport-proposal.md). The original raw-evidence
store and Key Vault retain no-bypass firewalls. No always-on Azure compute, premium
service, GPU, new tenant-wide mail grant, mailbox write or send permission was added.
Event Grid operations and Standard LRS storage remain metered.

## Recovery, ordering and accounting

- Each enrolled folder has its own encrypted opaque Graph delta cursor, generation,
  next-attempt time, lease receipt and freshness state. Graph's slash and OData
  folder-key URL forms are validated against the exact enrolled mailbox/folder;
  cursors are reused verbatim. External origins, other folders and redirects fail closed.
- A delta page's accepted item references and its next cursor commit in the same
  transaction. A crash before commit leaves both unapplied. A retry after commit
  reuses stable event/version keys, without duplicate logical versions or analysis work.
- HTTP 401 gets one forced token refresh; throttling respects bounded `Retry-After`.
  Retryable inbox work uses backoff, fenced receipts and a five-attempt poison state.
  Scoped replay requires the exact source/event reference and unexpired input.
- Missed notifications and subscription lifecycle events degrade coverage and trigger
  reconciliation. Subscriptions renew before expiry; removed or expired subscriptions
  can be recreated by the collector when its endpoint is configured. The bounded
  `watch` loop also reconciles if queue delivery fails.
- An expired/invalid delta cursor resets only that partition and records a historical
  gap. Full scoped resynchronization can recover **current state**. A message created
  and deleted entirely during an outage, or an intermediate overwritten version, can
  remain unrecoverable. Unknown lost-event counts stay null. Recovery never means
  that historical send activity was absent.
- Message moves within the enrollment retain the immutable copy identity. A failed
  read, a deleted item or a move outside scope invalidates pending work and records an
  explicit limitation. A removal notification alone is not treated as proof of deletion.
- Older responses cannot replace a newer version. Editing supersedes both pending
  queues and removes the old transient content input. Analysis completion is fenced
  to the current version and worker receipt. Agent evidence and content inference
  have independent leases and completion states.
- Mailbox copy identities include the source and case-sensitive immutable ID.
  Delivery copies sharing an Internet Message-ID receive an **unverified candidate
  group**, while their records and executor context remain distinct. A supplied header
  cannot merge actors or establish a verified cross-copy relationship; stronger joins
  belong to the evidence/correlation implementation.

`GET /v1/ingestion/sources/{source_ref}` exposes subscriptions, checkpoint freshness,
queue state/age, native poison count, message/version inventory and gaps. It requires
a validated API identity and a server-owned source-to-mailbox entitlement. It returns
references and status metadata, never bodies, cursor tokens or source identifiers.
The standalone ingestion app is separate from the existing decision API. Source
references must be explicitly enrolled in its authorization policy; no role grants
an implicit mailbox bypass.

## Microsoft activity sources

Office 365 Exchange audit is collected through Graph's asynchronous Purview Audit
Query API using the separately accepted `AuditLogsQuery-Exchange.Read.All` identity.
Queries are bounded to the pilot user and time window, with fifteen-minute overlap,
source-specific checkpoints, pagination and stable event deduplication. Normal query
latency is `catching_up`, while access errors, failures and throttling are explicit.
Only exact authorized synthetic Internet Message-ID matches or known collector-access
metadata are retained. A substring or approximate subject/time match is insufficient.
The retained envelope excludes body fields and arbitrary audit payloads.

The optional Graph activity adapter reads an explicitly configured Log Analytics
workspace with bounded overlap and fixed projected fields. It does not enable
logging or acquire permissions. The current tenant has no approved Graph activity
destination; its live coverage is explicitly unavailable. The alternative legacy
Office Management Activity feed is also disabled: no broader `ActivityFeed.Read`
grant was introduced merely to duplicate the approved Exchange audit source.
Fixtures exercise the eligible Graph adapter, including deduplication and source errors.

Collector application IDs are identified separately. Their reads remain available
for access auditing and are excluded from attribution signals. A third-party send
operation is evidence for later correlation, not an AI-agent verdict.

## Text extraction and minimum retention

The versioned offline extractor accepts plain text, HTML and bounded MIME, normalizes
Unicode to NFC, maps normalized spans back to Unicode code points in the decoded
body part, and separates authored, quoted, forwarded, signature, disclaimer and
ambiguous regions. Nested quotes preserve depth. It omits active/hidden HTML, images,
attachments and remote resources, and never performs network requests or executes HTML.

The labeled fixture suite covers HTML/plain equivalents, entities, combining Unicode,
nested replies/forwards, long disclaimers, mixed languages, short text, malformed and
oversized input, protected MIME and edited versions. Ambiguous extraction is ineligible
for statistical scoring. Spans are extraction heuristics, not proof of who wrote text.
Unsupported signature/quote conventions and unusual languages remain limitations.

English eligibility uses pinned `langdetect 1.0.9`, deterministic seed and 55 locally
bundled profiles verified by `config/language-artifacts.json`. This is a language
classifier, **not an AI-content detector**. English confidence, paragraph checks,
ASCII-letter coverage and a minimum of 100 authored words conservatively gate later
scoring. Short, unsupported and mixed-language text returns unknown. The shipped
Apache-2.0 LICENSE and upstream NOTICE are inventoried; package metadata incorrectly
says MIT and the discrepancy is recorded in the reviewed dependency policy.

Raw body text is transient. A normalized inference input is encrypted with a fresh
AES-GCM key wrapped to the content component's RSA public key, bound to the exact
version and a fifteen-minute expiry. Attribution/API identities cannot read these
capsules. Its private key is protected in operator storage and is intended only for
the content consumer; the current standby worker is not given the live key. Fixtures decrypt the actual
production-normalized text and verify authored/quoted input boundaries. No statistical
authorship model is installed in this phase; actual scoring, latency and accuracy
qualification remain required by the content-model phase.

Raw snapshots default off. The optional snapshot utility requires explicit synthetic
policy opt-in, encrypts snapshots, denies reads after seven days and safely purges only
its own validated files. Inbox locators and audit evidence expire at seven days;
version metadata and gaps at thirty days. Raw bodies never enter SQL summaries,
queue diagnostics or health output. Operational cursors remain encrypted while a
source is enrolled. Expired inputs cannot support exact replay; recollection or an
approved retained snapshot is required. Run operator retention maintenance regularly;
encrypted persistence and expiry checks do not replace physical deletion.
