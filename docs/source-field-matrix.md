## Correlation rules

Keep Graph IDs, Outlook UI IDs, Internet Message-ID, request IDs, audit item IDs and source run IDs as separate namespaces. IDs from one mailbox copy are not interchangeable with another copy. Internet Message-ID is case-sensitive input in this spike and is not a globally trusted primary key. Record scope and digest, reject ambiguous mappings, and retain the original source.

The authored signed-contract route requires a trusted actor-specific completed send, authorized observation, exact identifier/digest binding, valid evidence signature and no conflicting executor. The live native-audit route authenticates Microsoft through the authorized Graph session, requires a successful item-specific Send by the enrolled connector, and joins a unique Sent Items copy within the same tenant/mailbox. It captures MIME and verifies its Message-ID; the snapshot hash is collector integrity metadata, not a Microsoft signature on the body. Accepted/failed operations, drafting, recipient reads, header declarations and unmatched receipts remain unknown. Exact receipt replay is idempotent; a new message cannot reuse another message's receipt. A source signature authenticates the enrolled issuer, not causality or truthful authorship by itself.

Do not label a reconstructed operator JSON record as a vendor-issued receipt. The current Claude response's missing send-to-message identifier remains a source telemetry gap. The additional authenticated Exchange Send event supplies an independent item-specific mapping for this narrow route. The actual audit/store immutable ID did not establish equivalence to the Graph immutable ID through the attempted conversions; do not concatenate, strip prefixes or guess ID namespaces. Require a unique scoped Internet Message-ID join and expose ambiguity as unknown. This is not a general cross-mailbox correlation solution.

Measure source event time, emission time, collector first-seen time and decision time separately. EML transport transit and source-record emission intervals are not Microsoft audit-ingestion lag. No live audit-lag measurement is claimed until linked events can be observed through an authorized feed.
