## Reproduce setup and verification

Use the explicit subscription and approved identities in ignored work/private/secure-access/sandbox-settings.private.json. Keep that directory operator-restricted; never copy it into a PR, image or CI artifact. Cloud setup runs as the human administrator, separately from product workers. It needs the already available Azure/Entra and Exchange administration rights. Do not grant those administration rights to a collector.

1. Install locked dependencies and run python scripts/bootstrap-administration.py. The Exchange module is downloaded from PowerShell Gallery at its pinned version and SHA-256, without global installation.
2. Run python scripts/configure-tenant-access.py --config PRIVATE_CONFIG to review the registration plan. Add --apply only for the accepted sandbox. The script creates distinct certificate registrations and exact API/audit role assignments; it grants no Entra mailbox application role.
3. Run pwsh -NoProfile -File scripts/configure-mailbox-access.ps1 -ConfigurationPath PRIVATE_CONFIG to review the Exchange plan. Add -Apply for the accepted scope. The exact Entra object ID filter must resolve to one mailbox. The dedicated shared control remains outside scope and sign-in disabled.
4. Compile with python scripts/validate-infrastructure.py. Run python scripts/configure-azure-access.py --config PRIVATE_CONFIG for a group-scoped what-if, then --apply for the accepted minimal resources. The script refuses shared-resource modification/deletion, keeps operator-only IP firewalls, creates the signing key through the operator data plane and applies only exact queue/container/key grants. Existing keys are reused; provisioning is not a rotation command.
5. Start the local stack with python scripts/dev-services.py start. Runtime services use distinct SQL logins, row security and individual secret mounts. The migration identity alone has the local database owner credential. The API requires access tokens; development keys are fictional local test credentials, separate from Entra.
6. Run python scripts/verify-live-access.py --config PRIVATE_CONFIG. The mailbox, azure, audit and api sections can be run separately. Reports under work/reports contain status/boolean outcomes. Raw responses stay private. The audit read query may take minutes; unavailable or failed checks do not pass. No test attempts an email mutation or delivery.
7. On Windows, run pwsh -NoProfile -File scripts/protect-local-access.ps1 -Apply to restrict private evidence and local secrets to the operator, SYSTEM and local administrators. Unix local test material uses an owner-only parent directory. Product source and the client workbook are not targeted.

Exchange permission caches can take time to reflect changes. Do not weaken the scope or repeatedly broaden permissions to force a test to pass. Inspect both Exchange assignments and Entra app-role/delegated-grant inventories, then retry the bounded test when propagation warrants it. The Exchange simulator is supporting evidence; actual allowed/denied Graph calls are required.

## Credentials and key rotation

The hybrid Windows operator signs short-lived client assertions with separate non-exportable 3072-bit CNG certificates in CurrentUser/My. Entra stores only public certificates. Certificates expire after ninety days; MSAL tokens stay in memory. The host operator can use all six credentials and is trusted as the sandbox administrator. Separate credentials demonstrate service authorization boundaries; this setup is not protection against a compromised host administrator. Content containers receive no Windows key-store access, Graph credential or other worker secret. Introduce hosted managed identities when cloud runtime is deployed.

For certificate rotation, create a new non-exportable certificate for the exact workload alias with the reviewed certificate helper. Append its public certificate to only the matching tagged registration, retaining the old public credential during verification. Update the private manifest atomically, acquire a fresh token and rerun that workload's positive/negative tests. After successful cutover, remove only the old dedicated credential by its recorded key ID and verify it can no longer acquire a fresh token. Keep rollback metadata private. Never export a private certificate or log an assertion/token. Execute and record a complete overlap/cutover/revocation exercise during the later rotation/recovery qualification milestone.

For the evidence key, create a new version of evidence-signing through the operator data endpoint. Keep the vault firewall restricted and retain old public verification versions for at least the thirty-day decision window and any approved backup retention. Verify new-version signing and both new/old-version verification before changing the active version. The attribution identity can sign/verify; the API can verify only; neither can administer the key. Routine deployment reuses the existing key instead of rotating it.

## Audit, retention and scope changes

Resource-scoped Key Vault, Blob and Queue access diagnostics go to the existing approved East US workspace. Azure diagnostics include service-managed identity/network/request metadata inside that boundary. Product security records contain only category, outcome and pseudonymous references. Do not log bodies, authorization headers, raw source results or credentials. Review only the new project resources' events. A mailbox filter does not constrain the audit identity's tenant-wide Exchange visibility.

Raw synthetic blobs have seven-day lifecycle deletion and no blob versioning/soft-delete backup. Application reads deny expired raw references even while asynchronous Azure cleanup is pending. Blob Reader RBAC itself has no timestamp restriction. API SQL row security hides expired decisions at thirty days; physical decision cleanup and backup/restore qualification remain later work. Private source captures follow the accepted seven-day exact-file cleanup policy; configuration and credential references are not raw message fixtures.

History connectors and public inference remain disabled. Selected-message add-in authorization is planned independently of collector rights; no add-in UI/sign-in is claimed here. If the operator IP changes, review an exact-IP firewall update through what-if; never substitute an allow-all rule or trusted-service bypass. Stop only the named local Compose project when idle. Azure Storage/Key Vault remain available for the next milestone and incur bounded metered use. Removing registrations, role assignments, the shared control or resources requires an exact reviewed cleanup scope; never delete the shared resource group.
