# Identity and minimum-retention boundaries

Status: secure synthetic sandbox identities and effective access tests implemented. Hosted production identities and rollout remain later work.

Mailbox collector, Exchange audit collector, attribution, content, API and access-test registrations have distinct non-exportable Windows certificates. Only the mailbox collector receives exact-mailbox Exchange Application RBAC; it has no parallel Entra mail grant. The separately accepted audit identity has broader Exchange-audit visibility and no mailbox-body access. API roles and server-side entitlements are independent of collector access. The retired feasibility reader stays retired. No sender, agent runtime or approval identity is declared.

The accepted cost-controlled deployment keeps compute/PostgreSQL local and uses dedicated LRS Storage and Standard Key Vault with exact data-plane grants and operator-IP firewalls. Local services have different SQL logins, row security and individual secret mounts. The content container has no external route or other worker credential. Bicep's earlier optional managed-identity declarations remain undeployed; migrate to hosted managed identities when cloud runtime is introduced. The Windows sandbox administrator remains trusted and can operate the six local key-store credentials.

Queues accept references only, with application and SQL checks against body-bearing payloads. API SQL row security and application queries hide decisions after thirty days; app roles cannot extend that retention. Raw blobs have seven-day lifecycle deletion with versioning/soft-delete disabled, plus application expiry checks before reads. Azure lifecycle cleanup is asynchronous and Blob Reader itself has no timestamp condition. Physical decision cleanup, backups/restore and executed rotation/revocation qualification remain later work. Content text has no retained database/logging field; model-absent processing remains unknown. No production customer data is authorized.
